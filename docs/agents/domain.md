# Domain Docs

## Before exploring

Read `CONTEXT.md` at the repository root and any relevant ADRs in `docs/adr/`.

If these files do not exist, proceed without flagging their absence. Create them when domain terms or durable decisions are resolved.

## File structure

This is a single-context repository:

- `CONTEXT.md` — domain glossary and project context
- `docs/adr/` — architectural decision records

## Vocabulary

Use terms as defined in `CONTEXT.md`. If a needed concept is missing, record the gap for `/domain-modeling`.

## ADR conflicts

If proposed work conflicts with an ADR, identify the conflict explicitly rather than silently overriding it.
